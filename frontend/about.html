How SARR finds packages

~700k PyPI packages by meaning — vector search in Qdrant, metadata from BigQuery, optional rerank, a top-10 ranked list on every search, optional Gemini top-3, plus MCP tools for agents.

The problem

Package registries are easy to search when you already know a name. They are harder when you only know the job: an HTTP client, a dataframe tool, something for retries. Keyword indexes reward exact tokens; they under-serve descriptive queries and rarely encode whether a project is widely used or still maintained.

SARR (Semantic Artifacts Retrieval and Ranking) indexes PyPI packages as semantic documents and returns a ranked list for natural-language queries. The live index covers about 700,000 packages — filtered from current PyPI BigQuery metadata with quality and popularity gates — not the full ~1M unfiltered catalog.

System design

Indexing is a rare GPU job (Colab, PyTorch). Serving embeds the query, runs ANN in Qdrant on vectors only, loads rich metadata from BigQuery, optionally reranks, then blends adoption and recency. If you check LLM, Vertex Gemini writes a grounded top-3 from those retrieved packages only. On Lambda the bi-encoder and cross-encoder run as ONNX. Both paths share BAAI/bge-small-en-v1.5 and the same document format.

Offline (Colab GPU)
PyPI BigQuery extract → Filter · build document → PyTorch embed → Qdrant (~700k vectors + name)
Online (Lambda / local API)
UI · CLI · MCP → API Gateway → ONNX query embed → Qdrant ANN → BigQuery metadata → Rerank · blend

End-to-end path

  1. Index offline. BigQuery pulls filtered PyPI metadata (recency, description length, stars/forks/SourceRank or long descriptions). Each package becomes a structured document, embedded with PyTorch, and upserted to Qdrant as vector + package name — not full metadata in the vector store. Watermark checkpoints resume long Colab runs.
  2. Encode the query online. The same bi-encoder checkpoint maps your search string into 384-d space (ONNX on Lambda).
  3. Retrieve neighbors. Cosine ANN over ~700k vectors returns the closest packages by embedding similarity.
  4. Hydrate metadata. The API batch-fetches summaries, stars, forks, URLs, and release dates from BigQuery for those names. Filters (e.g. min stars) apply here, not in Qdrant.
  5. Rerank when needed. With Rerank checked, an ONNX cross-encoder rescores the top‑k using BigQuery descriptions — after hydration, not from Qdrant payloads.
  6. Blend for usefulness. Final score mixes semantic relevance with adoption (stars, dependents, SourceRank) and release recency from BigQuery fields.
  7. Return top 10 to the UI. Classic search uses POST /v1/search with limit=10. The Search page renders all ten hits (score, summary, stars/forks when Libraries.io has them).
  8. Grounded recommendations (optional). With LLM, POST /v1/rag streams the same top 10 as ranked_list, then Gemini top-3 cited from those descriptions only.

What you see on Search

  • Ranked list (always up to 10). Semantic retrieval over ~700k vectors, BigQuery hydrate, optional rerank, then blend. Without LLM, this is the full answer.
  • Gemini block (optional). With LLM, three grounded picks appear below the ten cards. If generation fails, the ranked ten still stand.

Grounded RAG (what shipped)

Search and generation are separate. Classic search uses POST /v1/search. Checking LLM calls POST /v1/rag (SSE). Rerank only runs the cross-encoder; it does not call Gemini.

  1. Retrieve 50 neighbors (Qdrant) and hydrate from BigQuery.
  2. Optional MiniLM rerank on hydrated text; blend and keep the top 10 (RAG_CONTEXT_K=10) for the UI and Gemini context.
  3. Emit ranked_list with those 10 hits first (complete if Gemini fails).
  4. Vertex Gemini sees only name + description for those ten; returns three cited picks.
  5. Backend drops hallucinated package names; UI marks LLM output separately from the ten ranked cards.

Compared with PyPI.org search

Typical registry search

  • Strong on exact names and known keywords
  • Struggles when the query is a use-case, not a title
  • Little visibility into “is this still maintained?”

SARR

  • ~700k filtered PyPI corpus (vectors-only in Qdrant)
  • Matches intent in embedding space
  • Handles descriptive queries without exact lexical overlap
  • Top-10 ranked list; adoption/recency from BigQuery when available
  • Optional Gemini top-3 from the retrieved ten only
  • MCP tools for agents

Models and systems choices

BAAI/bge-small-en-v1.5 (384-d) keeps indexing ~700k documents feasible on a Colab T4. Splitting metadata to BigQuery keeps Qdrant lean (vectors + name) while still reranking on fresh summaries. Popularity signals come from a Libraries.io join at ETL and query time.
